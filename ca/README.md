# `ca/` &mdash; root CA staging

Public CA certificates that get baked into the built MayaOS image.

## What goes here

- **Public PEMs only.** Anything matching `*.pem`, `*.crt`, or `*.0` is fai
  game and committed.
- **Never private keys.** `.gitignore` blocks `*.key`, but verify before you
  commit. If you accidentally commit a private key, rotate it immediately.

## Adding a new root CA

```bash
# From the repo root:
./scripts/add-ca.sh /path/to/your-root-ca.pem
```

That script computes the Android `subject_hash_old` filename and stages the
PEM into `device-tree/mayaos/galaxy-s26-ultra/security/cacerts/<hash>.0`. The
build picks it up automatically via `mayaos_cf_s26ultra.mk`'s
`PRODUCT_COPY_FILES` directive.

## Verifying which CAs ended up in a built image

After `./vast/fetch-artifacts.sh` pulls the build outputs and you've booted
the image with Cuttlefish:

```bash
./scripts/verify-image.sh                       # connects via adb to launched cvd
adb shell ls /system/etc/security/cacerts/
adb shell openssl x509 -noout -subject -issuer \
    -in /system/etc/security/cacerts/<hash>.0
```

- **Validity**: 10 years from generation
- **Hashed filename**: `0899db77.0`
- **Private key**: NOT committed; was discarded after generation. Re-run
  `scripts/gen-demo-ca.sh` to regenerate the keypair if needed.

This demo cert exists so the first build works end-to-end without external
inputs. Replace it with your real corporate root for production.
